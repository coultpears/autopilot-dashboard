What this view requires from the data layer

  • Neon Postgres (or equivalent) with tables: properties, monthly_revshare, daily_metrics, reservations, property_projections.
  • Nightly ETL from Looker into Postgres — populates rolling 12mo per property + recomputes projections + recomputes cohort memberships.
  • Materialized views for the segments (refresh nightly): v_str_enabled, v_mixed, v_at_risk, etc.
  • Read endpoints: /api/portfolio-kpis, /api/leaderboard?type=top|ramp|risk, /api/grid?segment=…&sort=…. The grid endpoint replaces the existing /api/grid-data with paginated, server-sorted, cohort-filtered output.
  • Estimated migration effort: ~1 working day for schema + ETL + endpoint stubs. The dashboard frontend code already structured to accept this shape.
